# Full-SNV concordance workflow

This package audits genome-wide VCF chunks and computes mergeable SpliceAI–OpenSpliceAI or OpenSpliceAI seed-to-seed agreement statistics without creating a multi-billion-row pandas table. SpliceAI is a comparator here, not biological truth.

The prespecified research questions, estimands, conclusion rules, and finality
contract are in [`STUDY_PROTOCOL.md`](STUDY_PROTOCOL.md).

The file/schema and interpretation inventory is available as Markdown in
[`FORMAT_AND_ANALYSIS.md`](FORMAT_AND_ANALYSIS.md) and as a self-contained HTML
mirror in [`FORMAT_AND_ANALYSIS.html`](FORMAT_AND_ANALYSIS.html). Final
run-specific reports are generated by `render-report` as `report.md` and
`report.html`.

Run commands from the repository root with the intended environment explicitly selected:

```bash
/home/kchao10/miniconda3/envs/pytorch_cuda/bin/python \
  -m validation.full_snv_concordance --help
```

## Input model and normalization

The analysis unit is `(CHROM, POS, REF, ALT, gene)`, not a VCF row. Source chunks can repeat the same variant once for every overlapping gene. OpenSpliceAI may repeat a prediction, emit only the MANE-selected gene, or omit the INFO value for a source row whose gene is outside its scoring annotation. The parser therefore:

- streams consecutive variant groups;
- explodes comma-separated ten-field annotations;
- matches only exact allele and gene symbols;
- deduplicates identical repeated annotations;
- excludes and counts conflicting values for the same method/gene;
- reports left-only, right-only, gene-mismatch, malformed, and missing-prediction coverage;
- canonicalizes textual negative zero to `0.0`;
- treats DP=0 as the valid site at the variant position after both event scores pass the selected threshold.

Mapper boundary groups are reduced separately. If a provisional pair list has a missing source chunk, groups touching that gap are conservatively excluded and counted as `excluded_incomplete_edge_fragments`; they are never joined across the gap.

## Audit and pair-list construction

An audit input is a headered TSV:

```text
chunk_id  source_vcf  prediction_vcf  seed
1         /path/snv.hg38_1.vcf        /path/snv.hg38_1_openspliceai.vcf rs10
```

Run a structural and source-preservation audit:

```bash
python -m validation.full_snv_concordance audit \
  --pairs-file candidate-pairs.tsv \
  --output audit.json \
  --parquet audit.parquet \
  --distance 50
```

A valid chunk has a complete VCF header and final newline, an `OpenSpliceAI` INFO declaration, identical source fields/SpliceAI INFO after removing OpenSpliceAI, equal row counts, valid ten-field annotations wherever a prediction is present, and DP values within `[-D,+D]`. Missing predictions are structurally preserved and are reported as coverage/gene-mismatch evidence rather than converted to zero. The audit snapshot records exact byte sizes, nanosecond mtimes, record counts, canonical source identities, and raw input/output SHA-256 hashes.

Build numerically sorted, audit-approved mapper inputs without manually editing paths:

```bash
python -m validation.full_snv_concordance build-pairs \
  --left-manifest rs10-audit.tsv \
  --concordance-output rs10-valid.tsv \
  --right-manifest rs13-audit.tsv \
  --seeds-output rs10-rs13-overlap.tsv
```

The builder accepts headered TSV/CSV or this package's audit JSON. Common campaign aliases such as `input_path`, `output_path`, and `status` are recognized, including the scoring campaign's `input_size`/`output_size`, `input_records`/`output_records`, and `input_source_digest`/`output_source_digest` snapshot names. Accepted rows must contain the complete audited snapshot, including raw file hashes. Both the campaign's length-prefixed source digest and the package's canonical record digest are verified when mapper jobs consume a pair. The builder freezes those fields plus the audit-manifest SHA-256 into each pair row; seed rows bind both outputs and both source identities. Use `--require-left-count 100000` for a candidate final rs10 release.

Campaign `provenance_state` values are carried into the frozen pairs as
`output_provenance_class`. Reports distinguish `receipt_bound`,
`receipt_invalid`, `legacy_log_supported`, and `legacy_unprovenanced`; an
invalid receipt is visible and is never treated as proof of model identity.

## Map, reduce, and report

For a local or single-shard smoke run:

```bash
python -m validation.full_snv_concordance map-concordance \
  --pairs-file rs10-valid.tsv --output maps/map-0.json \
  --task-index 0 --chunks-per-task 250 --run-label provisional

python -m validation.full_snv_concordance reduce-concordance \
  --input-dir maps --output summary.json \
  --pairs-file rs10-valid.tsv --expected-task-count 1 \
  --expected-total-chunks 100000 --finality provisional

python -m validation.full_snv_concordance render-report \
  --summary summary.json --output-dir report
```

Use `map-seeds`/`reduce-seeds` with the seed-overlap TSV. A final concordance reduction additionally requires pair IDs exactly `1..expected_total_chunks`; a final seed reduction requires `--finality final --expected-overlap-count N`. Both default to provisional. Reducers fail closed on missing or duplicate task indices, missing or duplicate chunk IDs, pair-list hash changes, unverified VCF snapshots, incompatible mapper configurations, mixed descriptive run labels, and mismatched comparison labels.

Current additive outputs include, for AG/AL/DG/DL/MAX:

- count, means, bias, Pearson correlation, Lin CCC, MAE, RMSE, zero rates, quantization-adjusted absolute error, and practical-equivalence counts;
- marginal, joint, and difference histograms;
- binned KS, Wasserstein-1, Jensen–Shannon, signed-difference quantiles, and
  approximate Spearman summaries with explicit approximation metadata;
- 0.1/0.2/0.5/0.8 call tables with agreement, Jaccard, Dice, kappa, MCC, and call-rate ratios;
- continuous-score summaries on union-signal subsets (`either >0` and either
  score at least 0.1/0.2/0.5, plus all configured thresholds);
- a right-score-rounded-to-two-decimals sensitivity comparison, including the
  changes in MAE, RMSE, and exact-match rate;
- a separate annotation-agnostic per-variant view that independently takes the
  event-wise maximum across valid genes on each side;
- dominant-event agreement with explicit ties;
- score-gated DP agreement within 0/1/2/5/10 bases;
- chromosome, gene, 1-Mb genomic block, REF>ALT substitution,
  dominant-event-pair, and site-event strata;
- deterministic gene- and 1-Mb-block cluster-bootstrap 95% intervals for
  additive MAX-score statistics;
- deterministic hash samples and bounded top-discrepancy records.

Compact sample/top tables can be written with `--parquet-dir` when `pyarrow` is available. `render-report` creates Markdown plus aggregate-density/event plots when matplotlib is available.

The exact-gene view is primary. The per-variant collapse is a sensitivity view:
it can pair signal assigned to different genes and therefore must not be
interpreted as gene concordance. Likewise, `substitution` is the VCF REF>ALT
class, not a trinucleotide context; the score VCF alone does not retain flanking
reference bases. Histogram metrics and Spearman are bounded-memory
approximations at the configured score-bin width. Pearson, Lin CCC, bias/error,
threshold counts, and DP counts use additive sums/counts rather than sampled
rows.

### Slurm launcher

The launcher is a dry run unless `--submit` is explicitly supplied:

```bash
validation/full_snv_concordance/slurm/run_map_reduce.sh \
  --kind concordance \
  --pairs-file rs10-valid.tsv \
  --output-dir /path/to/a-new-unique-run-directory \
  --run-label provisional-2026-08-01 \
  --finality provisional \
  --python /home/kchao10/miniconda3/envs/pytorch_cuda/bin/python
```

It uses account `ssalzbe1-chess`, partition `parallel`, 250 chunks/task, at most 12 concurrent tasks, one CPU/8 GB for maps, and four CPUs/32 GB for reduction. Task count is `ceil(pair rows / 250)`—400 for the final 100,000 chunks. Submission creates a new run directory, freezes the pair TSV read-only, records its SHA-256 and a package-code fingerprint, verifies both in every queued job, sets the repository working directory, and wires reducer/report jobs with `afterok` dependencies. Submission is transactional: if dependency creation or map release fails, only the jobs created by that launcher invocation are cancelled and the failure is recorded in `submission_status.tsv`.

The report renderer creates both `report.md` and a self-contained `report.html`,
with the generated PNG diagnostics embedded in the HTML. Reports are limited to
SpliceAI/OpenSpliceAI concordance and rs10/rs13 seed reproducibility; no external
database or functional-validation dataset is part of this workflow.

### Full-SNV scoring continuation operations

The authoritative continuation driver is
`/home/kchao10/data_ssalzbe1/khchao/OpenSpliceAI_precompute_scores/src/openspliceai_prediction_workflow/full_genome_scoring/campaign.sh`.
It uses the deep manifest rather than filename presence, packs only invalid
chunks (`PER_TASK=10`), serializes rs13 behind rs10, and holds the first array
until every plan has been validated. The older `run_selected.sh`, `submit.sh`,
`robust_submit.sh`, `fill_and_dedup.sh`, and `nuke_submit.sh` are historical
filename/dense-array submitters; they are retained for provenance but are not
the safe resume path.

After confirming that the Slurm controller is reachable and no matching
`osai_rs10*`/`osai_rs13*` jobs are live, run:

```bash
cd /home/kchao10/data_ssalzbe1/khchao/OpenSpliceAI_precompute_scores/src/openspliceai_prediction_workflow/full_genome_scoring
./campaign.sh audit --workers 24 rs10 rs13
./campaign.sh plan-resume rs10 rs13
./campaign.sh submit-resume rs10 rs13
```

The audit is intentionally repeated immediately before planning; a stale
legacy manifest is not accepted. If a prior held rs13 array is present, record
its exact job ID with `scontrol show job`, cancel only that exact stale job, then
re-run the duplicate-job check before `submit-resume`. Never release an old held
array. Once both arrays reconcile to 100,000 valid chunks, build the frozen
concordance/seed pair TSVs from the fresh manifests and launch the three
map/reduce/report runs above. The rs10 report is the primary final comparison;
rs13 and rs10-versus-rs13 remain provisional until their manifests and pair
coverage are complete.

### Automated continuation and reporting

The repository also contains a checkpointed supervisor that performs the
continuation, reconciliation, pair freezing, three final analysis launches,
and campaign-level Markdown/HTML summary. It uses a login-node bootstrap only
to wait for Slurm and submit one persistent CPU supervisor; all scoring work
still runs through the authoritative campaign driver.

Start it once (the process is lock-protected and safe to leave running while
the controller is down):

```bash
nohup validation/full_snv_concordance/automation/bootstrap.sh \
  --state-root /home/kchao10/data_ssalzbe1/khchao/OpenSpliceAI_precompute_scores/results/full_genome_scoring_campaign/automation \
  > /home/kchao10/data_ssalzbe1/khchao/OpenSpliceAI_precompute_scores/results/full_genome_scoring_campaign/automation/bootstrap.log 2>&1 &
```

The bootstrap retries Slurm with a 30-second-to-10-minute exponential
backoff. The supervisor checkpoints `current_state.json`, appends durable
events to `events.jsonl`, records every command log and job ID, emails state
changes to `MAILTO`, and self-requeues before its 48-hour CPU walltime. Read
the current state without changing anything with:

```bash
validation/full_snv_concordance/automation/status.sh \
  --state-root /home/kchao10/data_ssalzbe1/khchao/OpenSpliceAI_precompute_scores/results/full_genome_scoring_campaign/automation
```

The supervisor cancels a prior job only when the exact configured legacy ID,
name, held state, array signature, and legacy command match. It never releases
an old held array. Scheduler outages pause at a resumable state; malformed
manifests, provenance mismatches, failed validation, or failed final reports
stop fail-closed and preserve logs for correction.

## Explicit limitations of this implementation

Full-genome concordance is descriptive and does not establish biological
accuracy. The implementation does not infer exon/junction class or
trinucleotide sequence context from the score files, and histogram-derived rank
and distribution statistics are approximate. Cluster-bootstrap intervals
reflect either gene or 1-Mb-block resampling and do not remove every source of
dependence. Concordance does not establish biological accuracy.
